# 勤怠管理システム 要件定義書（詳細版）

## 1. システム概要

### 1-1. 目的
従業員の日々の勤務実績（勤務日、従業員名、シフト種別、勤務地）を正確に収集・蓄積する。蓄積されたデータを月別に集計・可視化し、管理者が容易に勤務状況を把握できる仕組みを構築する。

### 1-2. システム利用者と役割

| 役割 | 利用者 | 主な操作 |
| --- | --- | --- |
| 一般従業員 | 勤務する全従業員 | ・自身の勤務実績の入力（フォームまたはアプリ経由） |
| 管理者 | 勤怠管理担当者 | ・全従業員の勤怠実績の閲覧、集計、検索<br>・入力不備の確認と修正<br>・マスタデータ（従業員、勤務地）のメンテナンス |

### 1-3. システム構成
本システムは、以下のコンポーネントで構成される。

- 入力インターフェース: Googleフォーム または AppSheet等のNo-codeアプリ
- データストア (DB): Google スプレッドシート
- データ連携: フォーム（またはアプリ）からスプレッドシートへの自動書き込み
- 自動化・拡張機能: Google Apps Script (GAS) ※オプション

## 2. 機能要件

### 2-1. マスタ管理機能（管理者）
システムの基礎情報（選択肢）を管理する機能。スプレッドシート上の専用シートで管理する。

- **F-01: 従業員マスタ管理**  
  従業員の一覧を管理（追加、編集、削除）できる。  
  管理項目: 従業員ID（一意）、氏名、ステータス（在籍中、休職中、退職など）  
  「在籍中」の従業員のみが、入力フォームの選択肢に表示されること。

- **F-02: 勤務地マスタ管理**  
  勤務地の一覧を管理（追加、編集、削除）できる。  
  管理項目: 勤務地ID（一意）、勤務地名（例: 本社、A支店、在宅）

- **F-03: シフトマスタ管理**  
  シフト種別を管理（追加、編集、削除）できる。  
  管理項目: シフトID（一意）、シフト名（A, B）  
  （将来的な拡張項目として 開始時刻, 終了時刻 を持つことも想定する）

### 2-2. 勤怠入力機能（一般従業員）
日々の勤務実績を入力・送信する機能。

- **F-04: 勤怠実績入力フォーム**  
  従業員が勤務実績を入力するための専用フォーム（またはアプリ画面）を提供する。

- **F-05: 入力項目**  
  - 日付: 勤務した日付をカレンダー形式で選択できる。  
  - 氏名: 「従業員マスタ」から自身の氏名を選択できる（ドロップダウンリスト）。  
  - シフト: 「シフトマスタ」から「A」または「B」を選択できる（ドロップダウンまたはラジオボタン）。  
  - 勤務地: 「勤務地マスタ」から勤務した場所を選択できる（ドロップダウンリスト）。  
  - 備考: （任意入力）特記事項（遅刻理由、早退など）をテキストで入力できる。

- **F-06: 入力制御（バリデーション）**  
  - 日付, 氏名, シフト, 勤務地 はすべて必須入力とする。  
  - 日付 は、未来の日付を選択できないように制限する。（フォームでは難しいためアプリ推奨。フォームの場合は運用でカバー）  
  - 日付 は、入力日（本日）から過去30日より前の日付は入力できないように制限する（入力漏れ防止）。

- **F-07: データ送信**  
  送信ボタン押下時に、入力データがスプレッドシート（勤怠実績シート）に送信・記録される。送信時刻（タイムスタンプ）も自動で記録されること。

### 2-3. データ蓄積機能（システム）
入力されたデータを格納・管理する機能。

- **F-08: 勤怠実績データベース**  
  入力された全データは、スプレッドシートの「勤怠実績」シートに1行ずつ時系列で蓄積される。このシートは、原則として管理者以外は閲覧・編集不可とする。  
  蓄積項目: 実績ID (タイムスタンプ or 自動採番), 送信日時, 勤務日, 従業員ID (または氏名), シフトID (またはシフト名), 勤務地ID (または勤務地名), 備考

### 2-4. 閲覧・集計機能（管理者）
蓄積されたデータを管理者が確認・活用する機能。スプレッドシートの別シート（ダッシュボード）で実現する。

- **F-09: 勤怠実績一覧（生データ閲覧）**  
  管理者は「勤怠実績」シートで、全ての生データを閲覧できる。

- **F-10: データ修正・削除**  
  入力ミス（例: 従業員がシフトを間違えて入力）があった場合、管理者が「勤怠実績」シートの該当行を直接修正・削除できる。

- **F-11: 月別集計ダッシュボード**  
  管理者が「年」と「月」を選択すると、該当月の勤怠実績が自動で集計・表示される専用シート（ダッシュボード）を設ける。

- **F-12: 月別実績一覧（F-11の内部機能）**  
  指定した月（例: 2025年10月）の勤務実績データのみを一覧表示する。  
  表示項目: 日付, 氏名, シフト, 勤務地, 備考

- **F-13: 検索・フィルタリング（F-11の内部機能）**  
  F-12の一覧に対し、さらに以下の条件で絞り込み（フィルタリング）ができる。  
  - 氏名  
  - 勤務地  
  - シフト

- **F-14: 月別サマリー集計（F-11の内部機能）**  
  指定した月について、以下のサマリー情報を自動計算し表示する。（ピボットテーブルまたは関数で実装）  
  - 従業員別サマリー:  
    - 総出勤日数  
    - シフト別出勤回数（Aが何回、Bが何回）  
    - 勤務地別出勤回数（本社が何回、A支店が何回）  
  - 全体サマリー:  
    - 全従業員の延べ出勤日数  
    - シフト別総回数（全社でAが何回、Bが何回）  
    - 勤務地別総回数

- **F-15: データ出力**  
  管理者は、F-11で表示された「月別実績一覧」をCSVまたはExcelファイルとしてダウンロード（エクスポート）できる。（スプレッドシートの標準機能）

## 3. データ要件（スプレッドシート設計）

| シート名 | 目的 | 主な列構成案 |
| --- | --- | --- |
| ① 従業員マスタ | 従業員情報の管理。フォームの選択肢の元データ。 | 従業員ID, 氏名, 所属, ステータス (在籍中/退職) |
| ② 勤務地マスタ | 勤務地情報の管理。フォームの選択肢の元データ。 | 勤務地ID, 勤務地名 |
| ③ シフトマスタ | シフト情報の管理。フォームの選択肢の元データ。 | シフトID, シフト名 (A, B) |
| ④ 勤怠実績 | フォームからの全入力データを蓄積するDB本体。原則、直接編集しない。 | タイムスタンプ, 勤務日, 氏名, シフト, 勤務地, 備考 |
| ⑤ 月別集計ダッシュボード | 管理者用の閲覧・集計画面。 | ・年月指定セル<br>・サマリー表示エリア（F-14）<br>・月別実績一覧エリア（F-12, F-13）※QUERY関数等で④から自動抽出 |
| ⑥ (推奨) 設定・README | システムの操作説明、マスタ更新時の注意事項、関数のメモなどを記載。(自由記述) | - |

## 4. 非機能要件

### 4-1. ユーザビリティ（使いやすさ）
- 一般従業員の入力操作は、スマートフォンからでも迷わず完結できること。
- 入力項目は極力ドロップダウンリスト化し、手入力を排除することで表記揺れを防ぐ。
- 管理者の月別集計ダッシュボードは、年月を指定するだけで自動でデータが更新されること。

### 4-2. パフォーマンス（応答性）
- フォーム送信後、5秒以内にスプレッドシートにデータが反映されること。
- 勤怠実績データが年間1万行（例: 30人×365日）蓄積されても、月別集計ダッシュボードの表示・再計算が10秒以内に完了すること。

### 4-3. セキュリティ（アクセス権限）
- 一般従業員: 入力インターフェース（フォーム/アプリ）へのアクセス権限のみ。スプレッドシート本体（特に「勤怠実績」シート）への閲覧・編集権限は一切付与しない。
- 管理者: スプレッドシート（全シート）の編集権限。入力フォームの編集権限。

### 4-4. 拡張性・保守性
- 従業員、勤務地、シフトの増減は、管理者が「マスタ」シートを編集するだけで対応可能であること。
- （推奨）マスタシートを編集した場合、入力フォームの選択肢に自動で反映されること。（※Googleフォームの場合はGASによる自動化が必要。AppSheetの場合は自動で反映される）
- スプレッドシートの関数やGASコードには、保守のためにコメントを残すこと。

## 5. 運用要件

### 5-1. 入力ルール
- 従業員は、勤務実施日の翌営業日までに、自身で実績を入力すること。
- 入力ミスを発見した場合、従業員は速やかに管理者に口頭またはチャットで報告すること。
- データの修正は管理者のみが行う。

### 5-2. 締め処理ルール
- 管理者は、毎月1日（または第1営業日）に、前月分のデータに入力漏れや不備がないかを確認（F-11, F-14を活用）し、データを確定させる。

### 5-3. バックアップ
- スプレッドシートの「版の履歴」機能を主要なバックアップとする。
- 管理者は、月次締め処理完了後、スプレッドシートのコピーを作成し、バックアップとして別名保存することを推奨する。

### 5-4. マスタ更新
- 従業員の入退社、勤務地の新設・廃止が発生した場合、管理者は速やかに「マスタ」シートを更新し、入力フォームの選択肢に反映されていることを確認する。
